# KelpOS — FOSS Unix-like x86_64 Kernel (v0.4.0)

> **Made with AI** — KelpOS is developed with the help of AI coding agents. See [AI-POLICY.md](AI-POLICY.md) for how AI assistance is used and reviewed.

KelpOS is a free (GPL-3.0), Unix-like hobby kernel for **x86_64**,
written in **C17** with an optional **Rust** component (`rust/krust`).
It boots via the **Limine Boot Protocol**.

**v0.4.0 highlights:** a **mouse-driven window manager** desktop (PS/2
mouse driver with IRQ12: overlapping windows, title bars, dragging,
start menu, taskbar with a live RTC clock, flicker-free dirty-region
redraws and the boot wallpaper as an image on the desktop), a
**port of TinyGL 0.4 + GLU** (ska80 fork: textures, lighting, display
lists, vertex arrays, selection) with the upstream **GLGears** and
**Texobj** demos as desktop apps, **stb_image** for wallpaper decoding
(PNG/JPEG/GIF/TGA/BMP), `kelpinstall` rewritten in
**C** (real install by default, ANSI TUI, installed as a real command), the package manager is now
**`kpm` with install/uninstall** (persisted to `/etc/kpm/installed`),
more Unix commands (`rm touch wc head tail grep uname date env`), and
a remade boot menu wallpaper.

The framebuffer text terminal is drawn with an embedded 8x16 font
generated by `scripts/genfont.py` from the kbd `consolefont` package
(GPL-2.0+), so the shell is visible in the QEMU GUI window — not just
on serial.

## Packages

Shell commands are grouped into **packages**. The `core` package is
always present; the optional packages are `fs`, `users`, `fastfetch`,
`diskfs`, `about`, `mem`, `crc`, `cowsay`, `fortune`, and `crash`
(a debug command that forces a kernel panic).

- **Build-time selection** — pass a package list to make:
  ```sh
  make PKGS="crc cowsay" iso
  ```
  The syntax is handled by `scripts/pkgconf.py` and also accepts
  `all`, `all -fortune` (everything except fortune), and plain
  removals like `-cowsay`.
- **Runtime install/uninstall** — the shell command `kpm` manages
  packages at runtime: `kpm list`, `kpm info <name>`,
  `kpm install <name>`, `kpm uninstall <name>`, `kpm update`. The
  installed set is mirrored to `/etc/kpm/installed`; `core` cannot be
  uninstalled. Uninstalling disables the commands (compiled-in code
  stays in the image — this is the honest equivalent for a
  single-binary kernel).

## Prerequisites

- `gcc` (cross-compiler `x86_64-elf-gcc` recommended; `x86_64-linux-gnu-gcc`
  or host `gcc` also work)
- `nasm`, `git`, `xorriso`
- `qemu-system-x86_64` for `make run` / `make test-qemu`
- optional: `cargo` (+ nightly) for the Rust component

## Quick start

```sh
make          # build the boot ISO, fully verbose (downloads Limine if needed)
make run      # build the ISO and boot it in QEMU
```

Console output runs over `serial stdio`. In addition, the framebuffer
terminal shows the shell text directly in the QEMU window (8x16 font).
Shell commands: `help`, `echo`, `uptime`, `mem`, `crc`, `about`,
`cowsay`, `fortune`, `kpm` (list/install/uninstall), `uname`, `date`,
`env`, `clear`, `reboot`, `shutdown`, `desktop` (window-manager
desktop), plus the packages `fs` (`ls pwd cd mkdir tree cat rm touch
wc head tail grep`), `users` (`adduser groupmod whoami id doas sudo`),
`fastfetch` and `diskfs` (`mounts diskls diskcat` — the FAT16 demo
disk shipped as a boot module is mounted at `/media/disk0`;
ext4/btrfs volumes are detected but read access lands with the M5
milestone).

### Boot entries

The Limine menu (with wallpaper) offers:

- **KelpOS** — normal boot: banner + shell
- **KelpOS (Silent Boot)** — no banner, straight into the desktop

## Graphics

The renderer is a **vendored port of TinyGL 0.4** (Fabrice Bellard,
maintained fork by ska80) plus its **GLU** subset — not a home-grown
subset. The platform layer `kernel/gfx/tgl_surface.c` owns one
`ZBuffer` per window and converts finished frames to the desktop's
packed `0xAARRGGBB` format. Two upstream demos run as desktop apps:

- **GLGears** — the classic lit, rotating red/green/blue gears
- **Texobj** — the upstream texture demo (texture mapping + swapping)

Both open a 320x240 interior window, animate at ~25 fps while they are
the topmost window, and support dragging, minimizing and closing like
the other windows. The vendored sources keep their MIT license; see
[`kernel/gfx/tinygl/PORTING.md`](kernel/gfx/tinygl/PORTING.md) for the
upstream commit and every KelpOS-specific change.

Wallpapers are decoded by **stb_image** (`kernel/gfx/stb/`), so the
boot module may be BMP, PNG, JPEG, GIF or TGA (see
[`kernel/gfx/stb/README.md`](kernel/gfx/stb/README.md)).

## Installer

`kelpinstall` (C, built with `make kelpinstall` → `build/kelpinstall`)
is a **real command** — it is not meant to be run from `build/` by
accident. Install it explicitly first (`sudo make install`, prefix
configurable with `PREFIX`, default `/usr/local/bin`), then run it as
`kelpinstall`. It is an ANSI TUI that picks the **Device of Choice**
and the packages to build into the kernel, then partitions the disk
(MBR, FAT32 at LBA 2048), copies the payload and installs the Limine
BIOS stage. **It really installs by default** — nothing is written
only with the explicit `--dry-run` flag. Every real install shows
**3 warnings** (data loss, hobby software, wrong-disk risk) and
requires root + confirmation by typing the device name:

```sh
make kelpinstall
sudo make install                      # install the command
kelpinstall --dry-run                  # print the plan, write nothing
sudo kelpinstall                       # TUI, real install (3 warnings)
kelpinstall --non-interactive /dev/sdX --packages fs,users,about
sudo make uninstall                    # remove the command again
```

## Tests

```sh
make test        # native unit tests (klibc, heap, ramfs/vfs/FAT)
make test-qemu   # boot smoke test in QEMU (waits for KELPOS_SMOKE_OK)
```

`make test-qemu` greps the serial console output for the marker
`KELPOS_SMOKE_OK`.

## Rust option

```sh
rustup target add x86_64-unknown-none   # one-time setup (requires rustup)
make rust    # builds libkrust.a
make kernel  # links libkrust.a automatically if present
```

If the target is missing (e.g. Fedora system Rust without rustup),
`make rust` fails — the kernel stays fully functional (C fallback).
The `crc` command shows whether the Rust or the C fallback version ran.
